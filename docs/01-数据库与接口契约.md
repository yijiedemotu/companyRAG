# KnowFlow 数据库与接口契约

> **这是前后端、数据库、向量库之间的唯一契约。** 任何实现细节与本文冲突，以本文为准。
> 修改接口或表结构，必须同步改本文件。

---

## 一、约定

| 项 | 约定 |
| --- | --- |
| API 前缀 | `/api/v1`（`/health` `/ready` `/metrics` 在根路径） |
| 内容类型 | `application/json; charset=utf-8`；上传用 `multipart/form-data` |
| 流式 | `text/event-stream`（SSE） |
| 时间 | 数据库统一 `DATETIME(6)` 存 **UTC**；JSON 里输出 ISO8601 带 `Z` |
| 分页 | 请求 `page`（从 1 开始，默认 1）+ `size`（默认 20，最大 100）；响应统一 `Page[T]` |
| 标识 | 主键 `BIGINT UNSIGNED AUTO_INCREMENT`；对外 trace 用 `VARCHAR(64)` UUID |
| 命名 | 表名/字段名 `snake_case`；`id` 是主键，外键统一 `<表名单数>_id` |
| 软删除 | 仅 `knowledge_bases` / `documents` / `conversations` 有 `deleted_at`；查询默认过滤 |
| 金额 | `DECIMAL(12,6)`，单位 USD |

`Page[T]` 响应结构：

```json
{ "items": [], "total": 0, "page": 1, "size": 20, "pages": 0 }
```

统一错误响应（**所有** 非 2xx）：

```json
{
  "error": {
    "code": "KB_NOT_FOUND",
    "message": "知识库不存在",
    "detail": null,
    "request_id": "0f3a...",
    "timestamp": "2026-01-01T00:00:00Z"
  }
}
```

## 一之二、授权策略（**默认需要，例外公开**）

**所有业务接口都要求 `Authorization: Bearer <access_token>`，只有两类例外：**

| 例外 | 路径 | 为什么必须公开 |
| --- | --- | --- |
| 登录 / 注册 | `POST /api/v1/auth/register`、`POST /api/v1/auth/login` | 未登录时必须可用，否则没人能拿到 token |
| 运维探针 | `GET /health`、`GET /ready`、`GET /metrics`（**根路径，不带 `/api/v1`**） | 服务"半死不活"时也要能回答；拿不到 token 的时候往往正是需要看 `/health` 的时候 |

**授权粒度**：

- **读**：任何已登录用户可读所有知识库、文档、会话、评测与可观测数据
  （单租户企业知识库，资料是共享的）；
- **写**：知识库与文档的增删改**仅限创建者本人或 `admin`**（`KBService.ensure_owner`）；
- **会话**：只能读写自己的会话；访问别人的会话返回 **404 而不是 403**
  （不泄露"这个 id 存在但不属于你"）。

> ⚠ **这一节是修出来的，不是一开始就这么设计的。**
>
> 最初的做法是"逐个端点在函数签名里声明鉴权依赖"，理由是"读起来直观"。
> 后来写 HTTP 冒烟时发现 `GET /kbs` 不带 token 竟然返回 **200 + 正常业务数据**；
> 写脚本审计后发现 **39 个端点里有 21 个漏了鉴权**，包括
> `GET /kbs/{id}`、`GET /documents/{id}`、`GET /kbs/{id}/stats`、`POST /kbs/{id}/search`、
> `GET /eval/*`（8 个）、`GET /obs/*`（4 个）。
> 它们全都**返回 200 + 正常数据**，所以任何"断言字段对不对"的功能测试都发现不了。
>
> 现在的做法是**路由级默认要求**：
>
> ```python
> AUTH_REQUIRED = [Depends(get_current_user)]
> api_router.include_router(knowledge_bases.router, dependencies=AUTH_REQUIRED)
> ```
>
> 任何**将来新增**的端点都会自动受保护，确实要公开的才显式排除。
> **安全属性不能靠"每个人记得写"，必须靠"默认安全"** —— 默认值的方向决定了犯错时的后果。
>
> 门禁：`backend/scripts/audit_auth.py`（读 FastAPI 真实依赖图，
> 当前 34 个受保护 / 2 个刻意公开 / **0 漏洞**），已接入 CI。

## 二、错误码表

| HTTP | code | 触发场景 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 业务规则不满足（如 chunk_overlap ≥ chunk_size） |
| 400 | `UNSUPPORTED_FILE_TYPE` | 扩展名不在白名单 |
| 400 | `FILE_TOO_LARGE` | 超过 `MAX_UPLOAD_MB` |
| 400 | `DOCUMENT_PARSE_ERROR` | 解析失败（加密 PDF / 未知编码 / 无文本） |
| 400 | `DOCUMENT_EMPTY` | 解析后无有效文本 |
| 401 | `UNAUTHORIZED` | 无 token / token 过期 / 签名错 |
| 401 | `BAD_CREDENTIALS` | 用户名或口令错 |
| 403 | `FORBIDDEN` | 非管理员访问管理接口 / 非本人资源 |
| 404 | `KB_NOT_FOUND` / `DOCUMENT_NOT_FOUND` / `CONVERSATION_NOT_FOUND` / `RUN_NOT_FOUND` / `TRACE_NOT_FOUND` | 不存在或已软删 |
| 409 | `KB_NAME_CONFLICT` | 同名知识库 |
| 409 | `USERNAME_CONFLICT` | 用户名已占用 |
| 409 | `DOCUMENT_DUPLICATE` | 同 KB 下同一 `sha256` 且未删除 |
| 422 | `REQUEST_VALIDATION_ERROR` | Pydantic 校验失败（FastAPI 默认，需改写成统一信封） |
| 429 | `RATE_LIMITED` | 超过限流 |
| 500 | `INTERNAL_ERROR` | 未捕获异常 |
| 502 | `UPSTREAM_ERROR` | 大模型 / embedding 服务调用失败 |
| 503 | `NOT_READY` | 数据库或向量库未就绪 |

## 四、向量库契约

`VectorStore` 协议（`backend/src/knowflow/vectorstore/base.py`）：

```python
class VectorStore(Protocol):
    backend: str
    dim: int

    def upsert(self, *, kb_id: int, items: Sequence[VectorItem]) -> int: ...
    def query(self, *, kb_id: int, vector: Sequence[float], top_k: int,
              where: dict | None = None) -> list[VectorHit]: ...
    def delete(self, *, kb_id: int, doc_id: int | None = None,
               vector_ids: Sequence[str] | None = None) -> int: ...
    def count(self, *, kb_id: int | None = None) -> int: ...
    def list_vector_ids(self, *, kb_id: int, doc_id: int | None = None) -> list[str]: ...
    def reset(self, *, kb_id: int | None = None) -> None: ...
```

- `VectorItem = {id, vector, content, metadata}`；`metadata` 固定含
  `kb_id, doc_id, doc_name, chunk_index, page_no, section_path, ext, created_at`。
- `VectorHit = {id, score, content, metadata}`，**`score` 一律是「越大越相似」**。
  Chroma 返回的是**距离**（越小越相似），实现里必须做 `1 - distance` 转换。
- 集合命名：`knowflow_kb_{kb_id}`（按 KB 隔离，删除 KB = drop 集合，最省事也最干净）。
- 距离：`hnsw:space = cosine`；写入前向量必须 **L2 归一化**。

## 五、REST 接口清单

### 5.1 认证 `/api/v1/auth`

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| POST | `/auth/register` | `{username, password, display_name?}` | 201 `TokenOut` |
| POST | `/auth/login` | `{username, password}` | 200 `TokenOut` |
| GET | `/auth/me` | — | 200 `UserOut` |

`TokenOut = {access_token, token_type:"bearer", expires_in, user: UserOut}`
`UserOut = {id, username, display_name, role, is_active, created_at}`

注册规则：`username` 3–32 位 `[A-Za-z0-9_]`；`password` ≥ 6 位。
**第一个注册的用户自动成为 `admin`**（方便本地演示与 CI）。

### 5.2 知识库 `/api/v1/kbs`

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| GET | `/kbs` | `?page&size&keyword` | `Page[KBOut]` |
| POST | `/kbs` | `{name, description?, chunk_size?, chunk_overlap?}` | 201 `KBOut` |
| GET | `/kbs/{kb_id}` | — | `KBOut` |
| PATCH | `/kbs/{kb_id}` | `{name?, description?, chunk_size?, chunk_overlap?, is_active?}` | `KBOut` |
| DELETE | `/kbs/{kb_id}` | — | 204（软删 + 清向量集合 + 清 BM25） |
| GET | `/kbs/{kb_id}/stats` | — | `KBStatsOut` |

`KBOut = {id, name, description, owner_id, embedding_provider, embedding_model,
embedding_dim, chunk_size, chunk_overlap, is_active, doc_count, chunk_count, created_at}`
`KBStatsOut = {kb_id, doc_count, ready_doc_count, chunk_count, vector_count, bm25_doc_count,
total_chars, total_tokens, consistent: bool}`

> `consistent` = **`chunk_count == vector_count == bm25_doc_count`**（三方一致），
> 不一致时前端要能看到红点——
> **把静默降级变可见**。

### 5.3 文档 `/api/v1`

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| POST | `/kbs/{kb_id}/documents` | multipart `file` | 201 `DocumentOut` |
| GET | `/kbs/{kb_id}/documents` | `?page&size&status` | `Page[DocumentOut]` |
| GET | `/documents/{doc_id}` | — | `DocumentOut` |
| DELETE | `/documents/{doc_id}` | — | 204（软删 + 清向量 + 清 chunks + 重建 BM25） |
| GET | `/documents/{doc_id}/chunks` | `?page&size` | `Page[ChunkOut]` |

`DocumentOut = {id, kb_id, filename, ext, size_bytes, status, parser, page_count,
char_count, chunk_count, token_count, ingest_ms, error_code, error_message, created_at}`
`ChunkOut = {id, doc_id, chunk_index, content, char_count, token_count, page_no,
section_path, vector_id}`

允许扩展名：`md, markdown, txt, pdf, csv, json`。

### 5.6 SSE 事件流（`POST /chat/stream`）

`Content-Type: text/event-stream`，帧格式 `event: <name>\ndata: <json>\n\n`。
**顺序保证**：`meta` → (`trace`|`tool`|`reflect`)* → `sources` → `token`* → `done` → `end`。
任何阶段出错：发 `error` 帧，然后 `end`。前端只需处理这 8 种事件。

| event | data | 说明 |
| --- | --- | --- |
| `meta` | `{conversation_id, mode, trace_id, model, offline, embedding_mode}` | 第一帧，前端建气泡 |
| `trace` | `{node, status, duration_ms, detail}` | 图节点开始/结束，前端画「思考过程」 |
| `tool` | `{name, args, result_count, duration_ms}` | 工具调用（检索） |
| `sources` | `{sources: Source[]}` | 引用来源，**先于 token**，用户立刻有反馈 |
| `reflect` | `{round, passed, unsupported: object[], action}` | 自我反思结果 |
| `token` | `{text}` | 增量文本 |
| `done` | `ChatResponse` 的完整字段 | 收尾统计 |
| `error` | `{code, message, request_id}` | 错误 |
| `end` | `{}` | 关闭流 |

> `reflect.unsupported` 的元素是**对象**，形如 `{"sentence": "…", "reason": "…"}`，
> 由判官模型输出、原样透传（后端会容忍并归一裸字符串形态）。
> `reflect.action` 只用于前端展示，当前已知取值 `accept` / `regenerate`，
> **后端可自由新增取值（如 `abort`），这一项不做校验**——
> 一个展示字段不应该有能力让整帧解析失败、把用户已经看到的答案流打断。

## 七、前端契约

- 基址：`VITE_API_BASE_URL`（默认 `/api/v1`，Vite dev 用 proxy 转发到 `127.0.0.1:8000`）。
- 鉴权：`Authorization: Bearer <token>`，token 存 `localStorage`（key `knowflow.token`）。
- 401 处理：清 token → 跳登录页，并 toast「登录已过期」。
- SSE：`POST + fetch + ReadableStream`（**不能用 `EventSource`，因为要带 Authorization 头和 POST body**）。
  这一条是前端最容易踩的坑，实现里必须自己解析 `event:`/`data:` 分帧。
- 页面路由：`/login`、`/kbs`、`/kbs/:id`（文档管理）、`/chat`、`/chat/:conversationId`、
  `/search`（检索调试）、`/eval`、`/eval/runs/:id`、`/obs`、`/obs/traces/:traceId`。
