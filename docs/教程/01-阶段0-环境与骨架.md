# 阶段 0：环境与骨架

> **本阶段目标**：把工程骨架立起来，让 25 个关键依赖能被 `import`，并建立"src 布局"这个贯穿全项目的约定。
> **预计耗时**：40 分钟
> **前置阶段**：无（这是起点）
> **本阶段产出**：一个可用的 `.venv` + `backend/pyproject.toml` + 目录约定 + `check_env.py` 全绿

## 0. 为什么先做这一步

因为**后面 12 个阶段的所有验证命令都长这样**：

```powershell
.\.venv\Scripts\python.exe backend\scripts\_check_env.py
```

如果这一步没做对，后面出现的每一个 `ModuleNotFoundError`、`ImportError`、
"这个包版本怎么不对"，你都无法判断是**环境问题**还是**代码问题**。
这个项目有 25 个关键依赖（E1），其中深度学习栈（torch / transformers / sentence-transformers）
的版本耦合特别紧，靠"我本地能跑"是没法复现的。

还有第二个更隐蔽的理由：**src 布局**。

```
backend/
├── src/
│   └── knowflow/          ← 包在这里，不在 backend/ 下
├── tests/
├── scripts/
└── pyproject.toml
```

`src/` 布局的好处是"只有安装过的包才能被 import"——能挡住"因为我 `cd` 在
`backend/` 下所以 `import knowflow` 恰好成功"这种幻觉。代价是你必须先搞清
**三种 import 方式**，否则后面每个阶段都会卡在同一个地方：

| 场景 | 怎么让 `import knowflow` 成功 | 谁负责 |
| --- | --- | --- |
| 直接跑脚本 `python backend\scripts\xxx.py` | 脚本自己在开头 `sys.path.insert(0, BACKEND/"src")` | 每个脚本前 6 行 |
| 跑 `pytest` | `pyproject.toml` 的 `[tool.pytest.ini_options] testpaths` + 可编辑安装 | 工程配置 |
| 一次性的 `python -c "..."` 验证 | 设 `$env:PYTHONPATH='...\backend\src'` | 你自己 |

**这三条必须在这一阶段就搞明白**，否则你会在阶段 1 一开始就撞上
`ModuleNotFoundError: No module named 'knowflow'`，然后误以为"代码写错了"。

## 1. 要解决的问题

不做这一步，你会遇到的具体失败现象：

| 现象 | 真实原因 |
| --- | --- |
| `ModuleNotFoundError: No module named 'knowflow'` | 没设 `PYTHONPATH`，或没做可编辑安装；`src` 布局下包不在当前目录 |
| `ModuleNotFoundError: No module named 'langgraph.checkpoint.sqlite'` | 装的是 `langgraph` 但没装 `langgraph-checkpoint-sqlite`（两个包） |
| `AttributeError: module 'jwt' has no attribute 'encode'` | 装成了 `jwt` 而不是 `PyJWT`（同名不同包，PyJWT 的 import 名才是 `jwt`） |
| `URLError` / 卡住几分钟 | 首次 `import sentence_transformers` 或加载模型时在**下模型**（国内需要 `HF_ENDPOINT=https://hf-mirror.com`） |
| `ImportError: DLL load failed`（torch） | Python 版本与 torch wheel 不匹配（本机是 3.13.13 + `torch 2.12.1+cpu`） |
| 装完 `pip install -r requirements.txt` 用了很久但没报错，脚本仍失败 | 装到了全局 Python 而不是 `.venv` |

最后一条特别常见：`.venv\Scripts\python.exe -m pip install` 与 `pip install`
是两件事。**本教程所有命令都显式写解释器路径，就是为了避免这一类问题。**

### 2.2 关键代码 1：虚拟环境与依赖

```powershell
cd D:\Projects\pythonProjects\knowflow
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
```

**为什么依赖要"钉死版本"**：`backend/requirements.txt` 里全部是 `==`，
不是 `>=`。这个项目里最要命的一条耦合是：

```
chromadb 1.5.9  ←→  numpy 2.3.5  ←→  torch 2.12.1+cpu  ←→  transformers 5.18.0
```

深度学习栈的小版本漂移会直接改变 API（阶段 4 会讲一个真实例子：
`sentence-transformers 6.1.0` 把 `get_sentence_embedding_dimension()` 改名成
`get_embedding_dimension()`，旧名还能用但会刷 `FutureWarning`）。
**"我本地能跑"在这种依赖密度下不算证据**，钉住版本才算。

### 2.3 关键代码 2：唯一真相来源的工程配置

完整实现在 `backend/pyproject.toml`（219 行）。这里只摘三处**必须理解**的：

```toml
# backend/pyproject.toml L104-L115
[tool.ruff]
# ⚠ line-length = 100 是本仓库的**事实口径**，不是随手填的数：
#   源码里有大量中文注释/文档字符串，ruff 按 **unicode 显示宽度** 计数（一个汉字 = 2 列），
#   所以同样内容的行，中文比英文"长"一倍。88（ruff 默认）会让几乎所有带中文注释的
#   文件都过不了；100 是本仓库现有代码实际排布出来的宽度。
line-length = 100
target-version = "py311"
src = ["src", "tests", "scripts"]
extend-exclude = [
    ".venv",
    "alembic/versions",   # Alembic 自动生成的迁移脚本，格式由 alembic 模板决定，不参与人工 lint
]
```

🔻 **这是全项目最反直觉的一条配置**。`ruff` 默认 `line-length = 88`，
而它按 **Unicode 显示宽度**计长度：**一个汉字算 2 列**。
所以一行 45 个汉字的中文注释 = 90 列，用默认的 88 会**直接报错**，
而报错信息只告诉你"行太长"，完全不会提到"因为你写了中文"。
本仓库取 100 是因为**现有代码实际排布出来的最大宽度就是 100**，不是拍的。

```toml
# backend/pyproject.toml L104-L144（节选）
[tool.ruff.lint]
select = ["E", "F", "W", "I", "N", "UP", "B", "SIM", "RET", "S"]
ignore = [
    "E501",    # 行长由 [tool.ruff].line-length 统一管；再报一次是重复噪音
    "S101",    # assert：测试与 schemas/__init__.py 的契约自证都在用，属正常用法
    "B008",    # **必须 ignore**：FastAPI 的路由签名默认值是 `x: T = Depends(...)`，
               # flake8-bugbear 把"函数调用作为默认值"判为 B008，会让**每一条路由**都报错。
               # 这是 FastAPI 的官方推荐写法，不是 bug。
    "S311",    # evaluation/stats.py 用 random 做 **bootstrap 置信区间重抽样**，
               # 与密码学无关。换 secrets 反而会慢且不可复现（消融实验要可复现）。
]
```

**为什么逐条写 ignore 的理由**：`ignore` 列表是最容易被滥用的东西——
"为了过检查而关规则"和"因为规则误报而关规则"在 diff 里长得一模一样。
所以每一条后面都跟着原因，`B008` 这条尤其关键：**不关它，FastAPI 的每一条路由都会红**。

```toml
# backend/pyproject.toml L207-L219
[tool.pytest.ini_options]
testpaths = ["tests"]
# asyncio_mode=auto：async def 测试函数不用逐个加 @pytest.mark.asyncio
asyncio_mode = "auto"
# -q 让 CI 日志短一些；--strict-markers 保证拼错的 marker 直接失败而不是静默跳过
addopts = "-q --strict-markers"
filterwarnings = [
    "ignore::DeprecationWarning",
]
markers = [
    "integration: 需要 MySQL / 真实向量模型等外部依赖的用例（默认不下发）",
    "slow: 单条耗时较长的用例",
]
```

**`--strict-markers` 的价值**：写错 mark 名字（`@pytest.mark.integraton`）时，
pytest 默认**只是警告然后照跑**，于是你以为"集成测试被跳过了"，其实是全跑了。
加了它，拼错直接失败。

### 2.4 关键代码 3：依赖自检脚本

完整实现在 `backend/scripts/check_env.py`（44 行）。核心是"逐个 import 25 个包，
失败计数不是 0 就报错"：

```python
# backend/scripts/check_env.py L1-L45（全文，只有 44 行）
"""环境自检：确认所有依赖都能导入，并打印关键版本。"""

import importlib

MODS = [
    "fastapi", "uvicorn", "pydantic", "pydantic_settings", "sqlalchemy",
    "alembic", "pymysql", "langchain", "langchain_core", "langchain_openai",
    "langgraph", "langgraph.checkpoint.sqlite", "chromadb",
    "sentence_transformers", "numpy", "pypdf", "structlog", "jwt", "bcrypt",
    "httpx", "sse_starlette", "aiosqlite", "pytest", "torch", "transformers",
]

failed = 0
for name in MODS:
    try:
        mod = importlib.import_module(name)
        ver = getattr(mod, "__version__", "")
        print(f"  OK   {name:34s} {ver}")
    except Exception as exc:  # noqa: BLE001
        failed += 1
        print(f"  FAIL {name:34s} {type(exc).__name__}: {exc}")

print()
print("RESULT:", "ALL OK" if failed == 0 else f"{failed} FAILED")
```

**三处值得学的写法**：

1. **`importlib.import_module` 而不是 25 行 `import xxx`**：这样能统一拿到
   `__version__` 并统一处理异常。用 `import` 语句的话，第一个失败的包会让脚本
   直接崩，你只能一个一个改。
2. **捕获 `Exception` 而不是 `ImportError`**：`import torch` 失败可能抛
   `OSError`（DLL 问题）、`ImportError`（缺依赖）、甚至 `RuntimeError`。
   只捕 `ImportError` 会漏掉最常见的那一类。
3. **`RESULT:` 这一行是给人和给 CI 看的**：脚本退出码可用于门禁，
   而人只需要扫一眼最后一行。**教程后面每一步验证都遵守这个约定**。

⚠ `langgraph` 与 `langgraph.checkpoint.sqlite` 的 `__version__` 是空的
（E1 的真实输出里那两行版本号就是空的），这**不是错误**——它们没暴露 `__version__`。

### 2.5 目标目录骨架

```
knowflow/
├── .venv/                          # 虚拟环境（不提交）
├── backend/
│   ├── .env                        # 本地配置（不提交）
│   ├── .env.example                # 配置样例（提交）
│   ├── pyproject.toml              # 依赖 + ruff + mypy + pytest
│   ├── requirements.txt            # 运行期依赖（pip 安装的权威）
│   ├── requirements-dev.txt        # 开发依赖
│   ├── alembic.ini                 # ⚠ 必须纯 ASCII，阶段 2 会讲
│   ├── alembic/                    # env.py + versions/
│   ├── src/knowflow/               # 包本体（阶段 1 开始往里写）
│   ├── scripts/                    # 运维/自检脚本（不进 src）
│   └── tests/                      # pytest
├── data/                           # 运行期数据（不提交）
│   ├── samples/                    # 6 份示例文档
│   ├── uploads/                    # 上传的原文件
│   ├── chroma/                     # 向量库
│   └── eval_cases.jsonl            # 标注评测集
└── frontend/                       # 阶段 9
```

**为什么 `scripts/` 不在 `src/` 里**：`src/knowflow` 是**要被别人 import 的库**，
`scripts/` 是**自己跑的工具**。混在一起会导致脚本里的 `print`、`argparse`
污染库的公共接口，也会让 `pip install` 把运维脚本一起装进 site-packages。

## 4. 常见错误

| 错误信息 | 原因 | 解决 |
| --- | --- | --- |
| `无法将".venv\Scripts\python.exe"项识别为 cmdlet...` | 用了相对路径 `..\.venv\...`，但 PowerShell 的相对路径基准不是你以为的那个目录 | 用**绝对路径** `D:\...\.venv\Scripts\python.exe`，或先 `cd` 到位（本会话踩过这个） |
| `ModuleNotFoundError: No module named 'knowflow'` | `src` 布局 + 没设 `PYTHONPATH` | 脚本方式：开头插 `sys.path`；交互方式：设 `$env:PYTHONPATH` |
| `No module named 'langgraph.checkpoint.sqlite'` | 只装了 `langgraph`，没装 `langgraph-checkpoint-sqlite` | 按 `requirements.txt` 全量装 |
| `AttributeError: module 'jwt' has no attribute 'encode'` | 装了 `jwt` 包（不是 `PyJWT`） | `pip uninstall jwt` 然后装 `PyJWT==2.15.1` |
| `pip` 装完脚本仍失败 | 装到了全局 Python | 一律用 `.\.venv\Scripts\python.exe -m pip` |
| ruff 报大量"行太长"且都在中文注释行 | `line-length` 用了默认 88，而汉字按 2 列算 | 设 `line-length = 100`（见 §2.3） |
| 第一次 `import sentence_transformers` 卡住数分钟 | 在下 HuggingFace 模型 | 设 `HF_ENDPOINT=https://hf-mirror.com`；或阶段 4 用 `EMBEDDING_PROVIDER=hash` 跳过 |
| `ImportError: DLL load failed while importing torch` | torch wheel 与 Python 版本不匹配 | 按 `torch==2.12.1+cpu` 装 CPU 版 |
