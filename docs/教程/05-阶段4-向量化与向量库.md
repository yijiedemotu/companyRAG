# 阶段 4：向量化与向量库

> **本阶段目标**：把文本变成"归一化 + 越大越相似"的向量，并让"模型加载失败"这件事**可见但不断链**。
> **预计耗时**：90 分钟
> **前置阶段**：阶段 3
> **本阶段产出**：`embeddings/`（921 行）+ `vectorstore/`（1,024 行）+ 两个后端的等价语义

## 0. 为什么先做这一步

因为阶段 5 的融合需要一个**稳定含义的分数**。向量库返回的原始值是
**距离**（越小越相似，0 = 完全相同），而 BM25 的分数是**越大越好**。
如果不在这一层把"距离 → 相似度"统一掉，阶段 5 的
`hybrid` 融合会把"最相似的排到最后"——**而且不会报错**。

第二个理由：**降级路径必须与主路径同等对待**（`docs/00` 的选型原则第 3 条）。
如果向量化失败就 502，那么"没配 API Key、没下模型"的人 clone 下来根本跑不起来。
本阶段的核心设计目标是：

> **主实现（本地 BGE-M3 / 远程 API）挂了 → 自动降级到哈希兜底，
> 链路继续跑，但降级事实必须如实体现在 `/health` 里。**

第三个理由：**惰性加载**。如果 `build_embedder()` 就把 2GB 权重读进内存，
那么阶段 9 里每一个只查文档列表的请求都会连带启动模型。
所以"构造时不加载，第一次 `embed_*` 才加载"是本阶段的硬要求。

---

## 1. 要解决的问题

不做这一步，你会遇到的具体失败现象：

| 现象 | 真实原因 |
| --- | --- |
| 检索出来最相似的排到最后，接口 200、有结果 | Chroma 返回的是**距离**，直接当相似度用了 |
| 首次 `import knowflow` 花 2~5 秒，或离线环境直接崩 | 模块级 `import torch` |
| 装了 hash 兜底的环境（没装 torch）导入失败 | 没用 `TYPE_CHECKING` + 方法内 import |
| `Expected where to have exactly one operator` | Chroma 的 `where` 每层只能有一个算子 |
| 写进向量库的 `page_no` 读回来不见了 | Chroma **静默丢弃** None 值的 metadata（不是报错！） |
| 内存后端能按 `doc_id=3` 查到，Chroma 查不到 | 传的是字符串 `"3"`，而 Chroma 的比较是**强类型**的 |
| `ValueError: Expected ids to be a non-empty list` | `delete(ids=[])` 或空 `upsert` |
| 一次 `delete()` 返回 `int` 而另一次返回 `dict` | Chroma 返回 `{"deleted": N}`，不是整数 |
| 第一次写向量时静默下载 79MB 的 ONNX 模型 | 没传 `embedding_function=None` |
| 已存在的集合改了 `hnsw:space` 却不生效 | `hnsw:space` **只在创建集合时**生效 |
| `/health` 报 `embedding_mode=local`，但实际上跑的是哈希 | 降级状态没有如实上报 |
| NaN 出现在所有距离计算里 | 零向量被 L2 归一化（除以 0） |

倒数第二条是"不骗人硬规则"的直接违反，本阶段会用 `get_embedder_status()` 解决它。

### 2.2 关键代码 1：协议只要求 4 属性 + 2 方法

```python
# backend/src/knowflow/embeddings/base.py L44-L73（节选）
class Embedder(Protocol):
    """文本向量化器的统一契约。

    实现必须满足三条约定，缺一条都会在检索端变成难查的问题：

    1. `embed_documents` 与 `embed_query` 返回**同维度**且已 **L2 归一化**的向量
       （归一化后点积 == 余弦相似度，阈值 `VECTOR_MIN_SCORE` 才有稳定含义）；
    2. 空文本返回**零向量**，不抛异常；
    3. `dim` 必须等于向量库集合的维度 —— 换模型必须重建向量库。
    """

    provider: str
    model: str
    dim: int
    display_name: str

    def embed_documents(self, texts: Sequence[str]) -> list[list[float]]: ...
    def embed_query(self, text: str) -> list[float]: ...
```

**为什么"不要求继承"**：协议是结构化的（`Protocol`），单测里 20 行就能写个假实现。
这是本阶段能"完全不碰磁盘与网络"地测出等价语义的前提。

**为什么 `warmup()` / `is_loaded` 不进协议**（同文件 L14-L15）：

```
2. `warmup()` / `is_loaded` **不进协议**：hash 兜底没有模型可加载，写进协议会逼
   所有实现造假动作；需要预热的调用方统一用 `warmup_embedder()` 做「有则调用」。
```

**这条经验很通用**：协议里每多一个成员，就多一个"某些实现根本不需要、
只能写个空实现来凑"的成员。空实现是**噪音**，会让读者以为"这里真的做了什么"。

L2 归一化：

```python
# backend/src/knowflow/embeddings/base.py L76-L92
def l2_normalize(vec: Sequence[float]) -> list[float]:
    """L2 归一化：返回 `v / ||v||`。

    为什么必须归一化：Chroma 用 `cosine` 空间，余弦相似度的分母就是两个向量的
    模长；提前归一化后「点积 == 余弦相似度」，阈值才有稳定含义，也才能和 BM25
    的分数一起做融合。

    为什么是纯 python 而不是 numpy：本函数会被单测反复调用，且**不能**让 numpy
    成为 embeddings 的硬依赖 —— 只想跑 hash 兜底的离线环境也要能 import 本模块。

    零向量（`||v|| == 0`，空文本的产物）原样返回零向量：除以 0 会得到 NaN，
    而 NaN 一旦写进向量库，之后**所有**距离计算都会是 NaN，且不会有任何报错。
    """
    norm = math.sqrt(sum(float(x) * float(x) for x in vec))
    if norm == 0.0:
        return [0.0] * len(vec)
    return [float(x) / norm for x in vec]
```

🔻 **NaN 那一段是真事故级别的坑**。`vec / 0` 得到 NaN 而**不报错**，
NaN 写进向量库之后，与该向量比较的任何距离都是 NaN，
排序结果变成未定义——**接口 200、有结果、全错**。`if norm == 0.0` 这一行是保险丝。

**为什么不用 numpy**：`import numpy` 要 100~300ms，而
"只想验证链路通不通"的用户不该付这个代价。57 行的纯 Python 版本足够快。

### 2.4 关键代码 3：哈希兜底——hashing trick

```python
# backend/src/knowflow/embeddings/hash_embedder.py L46-L56
def iter_tokens(text: str) -> Iterator[str]:
    """产出 1-gram + 2-gram token（先丢掉空白与标点）。

    为什么不引 jieba：兜底实现要的是**零依赖 + 确定性**，分词质量对它是次要的；
    而且中文 `split()` 切出来是「一个词」，BM25 与哈希兜底都会直接失效，
    所以这里用字符级 n-gram —— 1-gram 保证不漏，2-gram 提供一点区分度。
    """
    chars = [ch.lower() for ch in text if ch.isalnum()]
    yield from chars
    for i in range(len(chars) - 1):
        yield chars[i] + chars[i + 1]
```

核心的累加：

```python
# backend/src/knowflow/embeddings/hash_embedder.py L86-L98
def _embed_one(self, text: str) -> list[float]:
    """把一条文本累加成一个向量。

    累加用 float 而不是 int：后续要 L2 归一化，用 float 避免一次多余的转换。
    """
    vec = zero_vector(self.dim)
    for token in iter_tokens(text):
        digest = hashlib.blake2b(token.encode("utf-8"), digest_size=_DIGEST_BYTES).digest()
        h = int.from_bytes(digest, "big")
        bucket = h % self.dim
        sign = 1.0 if (h >> _SIGN_SHIFT) & 1 == 0 else -1.0
        vec[bucket] += sign
    return l2_normalize(vec)
```

**三处细节**：

1. **`blake2b` 而不是 `hash()`**：Python 的 `hash()` 对 `str` 有**进程级随机盐**
   （`PYTHONHASHSEED`），同一段文本在两个进程里会得到不同的向量——
   那就等于"入库的向量和查询的向量不在同一空间"。`blake2b` 是确定性的。
2. **符号位 `(h >> 63) & 1`**：这是 random projection 的标准做法。
   两个不同 token 撞进同一个桶时，有 50% 概率**互相抵消**而不是叠加放大，
   降低哈希碰撞的破坏力。
3. **桶用低位、符号用最高位**：两者互不干扰（注释里写了）。

**它诚实的自我评价**（同文件 L22-L25）：

```
⚠️ **这是离线兜底，检索质量差。** 它没有语义：问「出差住房能报多少」和
文档里的「住宿标准 600 元」只要没有共同字，相似度就是 0。它存在的**唯一目的**
是让 CI 零成本、零网络跑通全链路（入库 → 检索 → 生成 → 评测 → `/health`），
以及在没有模型、没有 API Key 时链路不中断。**生产环境不要用它。**
```

**"降级实现也要写清楚它差在哪"**，这是文档诚实度的一部分。

### 2.5 关键代码 4：惰性加载与双检锁

```python
# backend/src/knowflow/embeddings/local_bge.py L165-L186（节选）
def _ensure_model(self) -> SentenceTransformer:
    """返回已加载的模型；需要时加载（双检锁，保证只加载一次）。"""
    if self._model is not None:
        return self._model
    with self._load_lock:
        # 双检：等锁期间可能已经有别的线程加载完了，直接复用
        if self._model is not None:
            return self._model
        source = self.resolve_model_source()
        device = self._resolve_device()
        started = time.perf_counter()
        try:
            # 延迟到真正要用时才 import：没装 sentence-transformers 的环境
            # （只跑 hash 兜底）依然能 import 本模块。
            from sentence_transformers import SentenceTransformer

            model = SentenceTransformer(source, device=device)
        except Exception as exc:
            raise EmbeddingError(
                f"加载本地向量模型失败（source={source}, device={device}）："
                f"{type(exc).__name__}: {exc}"
            ) from exc
```

**为什么模块级不 import torch**（同文件 L44-L45）：


**`TYPE_CHECKING` 这个惯用法在这里不是为了"避免循环 import"，
而是为了"模块导入必须保持轻量"**。`import torch` 要 2~5 秒；
如果放在模块级，那么阶段 9 里"列一下知识库"这种请求都会连带等 5 秒。

维度交叉校验：

```python
# backend/src/knowflow/embeddings/local_bge.py L188-L197

expected_dim = self._settings.embedding_dim
if actual_dim != expected_dim:

        "换 embedding 模型必须重建向量库：新旧向量的维度和语义空间都不同，"
        "混在同一个集合里会让检索结果完全错乱（且不会报错）。"
        "请清空向量库目录后重新入库，或先把 EMBEDDING_DIM 改成模型真实维度。"

```

**为什么要"交叉校验"而不是"信任配置"**：换模型会同时改变**维度**和**语义空间**。
放过去的表现是"检索结果全错但不报错"——这是最贵的 bug。
**能变成启动期异常的，绝不留给运行期。**

模型来源三级回退：

```python
# backend/src/knowflow/embeddings/local_bge.py L97-L127（节选）
def resolve_model_source(self) -> str:
    """按三级优先级决定模型来源，返回给 `SentenceTransformer` 的入参。

    1. `EMBEDDING_MODEL_PATH` 非空且目录存在 → 直接用该目录（完全离线，
       连 HF 的缓存/索引都不查）；
    2. 否则 `DATA_DIR/model_cache/<sanitized_model_name>` 存在 → 用该缓存目录；
    3. 否则用模型名（如 `BAAI/bge-m3`）交给 sentence-transformers 下载。
    """
    configured = self._settings.embedding_model_path.strip()
    if configured:
        path = Path(configured).expanduser()
        if path.is_dir():
            return str(path)
        # 配了却不存在：继续往下回退，但必须留下 warning，
        # 否则「以为在跑本地模型、其实在下模型/用兜底」这种事没人知道。
        logger.warning(
            "EMBEDDING_MODEL_PATH 指向的目录不存在，继续回退到缓存或模型下载",
            embedding_model_path=configured,
        )
```

**注意"配了却不存在"这一支为什么必须打 warning**：
静默回退到"下载模型"会让离线环境**卡住几分钟**（或直接失败），
而 warning 让这件事在日志里一眼可见。

维度读取要兼容 API 改名：

```python
# backend/src/knowflow/embeddings/local_bge.py L286-L300
def _read_embedding_dim(model: SentenceTransformer) -> int:
    """读取模型输出维度，兼容 sentence-transformers 6.x 的方法改名。

    6.1.0 起 `get_sentence_embedding_dimension()` 改名为 `get_embedding_dimension()`
    （旧名仍可用但会打 FutureWarning）。这里优先用新名，避免启动日志被警告刷屏。
    """
    getter = getattr(model, "get_embedding_dimension", None)
    if getter is None:
        getter = getattr(model, "get_sentence_embedding_dimension", None)
    if getter is None:
        raise EmbeddingError("无法从 sentence-transformers 模型读取输出维度")
```

🔻 **`getattr` 双路兼容**是本项目唯一一处"因为第三方库改名而必须写的兼容代码"。
不写的话不会立即报错（旧名还在），只会让每次启动都刷一条 `FutureWarning`。
**这类"不报错但很脏"的技术债，最容易被留在代码里**，所以本仓库选择顺手清掉。

### 2.6 关键代码 5：降级包装器——"可见但不断链"

```python
# backend/src/knowflow/embeddings/factory.py L11-L23
**关键设计取舍**：

1. **降级放在包装器里，不放在各实现里**：local 加载失败、api 401、api 超时
   都要走同一条路。写在一处才不会出现「本地实现会降级、api 实现直接 502」
   这种不一致；也让三个实现本身保持纯粹（只管好自己的事）。
2. **降级是「懒」的，不在 `build_embedder` 里加载模型**：local 是惰性加载，
   启动时加载 2GB 权重会拖慢所有接口，离线 CI 更不该加载。
3. **降级只发生一次且不可逆**：一旦确认主实现不可用就永久切到兜底，
   避免每次请求都先失败再降级（那会把延迟和日志都毁掉）。
4. **降级后 `provider` 变成 `hash`**：`provider` 表达「真正在用的实现」，
   而不是「配置里写的那个」——否则写进 KB 快照的 provider 就是假的。
```

第 4 条是"不骗人硬规则"在代码里的落地：

```python

def mode(self) -> str:
    """给 `/health` 的 `embedding_mode` 用，格式见接口契约。
```

运行时降级（`_with_fallback`）：

```python
# backend/src/knowflow/embeddings/factory.py L151-L161
def _with_fallback(self, operation: Callable[[Embedder], _T]) -> _T:
    active = self._active()
    try:
        return operation(active)
    except Exception as exc:
        if self._fallback is not None:
            # 兜底实现本身也失败了：真的没辙了，原样抛出，
            # 让上层转成 UPSTREAM_ERROR（而不是假装成功）。
            raise
        self._degrade(reason=_REASON_RUNTIME_FAILED, detail=_describe(exc), failed=active)
        return operation(self._active())
```

**注意"对同一批输入重试一次"而不是"返回空"**：`operation` 是闭包，
它捕获了原始的 `texts` / `text`，所以降级后能用**同一批输入**重跑。
如果只返回空列表，调用方会得到"向量化成功但零条向量"，
然后向量库和 MySQL 的数量就对不上了。

**降级原因用"短标识"而不是整段异常文本**（同文件 L45-L50）：

```python
# 降级原因用「短标识」而不是整段异常文本：
# 它要拼进 /health 的 embedding_mode（形如 hash(fallback:local_load_failed)），
# 完整异常文本进日志（degrade_detail 字段与 warning 日志里都有）。
_REASON_INIT_FAILED = "provider_init_failed"
_REASON_LOAD_FAILED = "load_failed"
_REASON_RUNTIME_FAILED = "runtime_failed"
```

**两者都要有，但分开存放**：`/health` 要的是**机器可读的稳定标识**，
日志要的是**完整的异常文本**。混在一起会导致 `/health` 的字符串随异常消息变化，
监控规则没法写。

### 2.7 关键代码 6：距离 → 相似度（本阶段最重要的一行）

```python
# backend/src/knowflow/vectorstore/chroma_store.py L228-L240
@staticmethod
def _distance_to_score(distance: float) -> float:
    """把 Chroma 的 **cosine 距离** 转成项目约定的**相似度**（越大越相似）。

    为什么是 `1 - distance`：`hnsw:space=cosine` 返回 `d = 1 - cos(a, b)`，
    0 表示方向完全相同、2 表示完全相反，所以它**越小越相似**。
    项目契约（以及 BM25 融合、`VECTOR_MIN_SCORE` 闸门）要求 score
    **越大越相似**，于是 `score = 1 - d`，即余弦相似度本身。

    ⚠️ 直接把 distance 当 score 用不会报错，只会让「最相似的排到最后」——
    检索看起来还能出结果，但全是错的。这是本文件最需要看清的一行。
    """
    return 1.0 - float(distance)
```

🔻 **这就是"接口 200、有结果、全错"的典型**。转换收在**一个函数**里、
带 docstring 说明、被测试覆盖——这是把一个"容易搞反且搞反后看起来还能用"的点
**隔离到一个地方**的标准做法。

### 2.8 关键代码 7：集合的获取与"禁止 Chroma 自带 EF"

```python
# backend/src/knowflow/vectorstore/chroma_store.py L98-L122
def _get_collection(self, kb_id: int) -> Collection:
    """取集合，不存在就创建（只在写入路径调用）。"""
    cached = self._collections.get(kb_id)
    if cached is not None:
        return cached
    # 双检锁：多线程并发 get_or_create_collection 有竞态（会报集合已存在），
    # 而且锁外的快速路径让高频检索不用每次都抢锁。
    with self._lock:
        cached = self._collections.get(kb_id)
        if cached is not None:
            return cached
        name = collection_name(kb_id)
        try:
            collection = self._client.get_or_create_collection(
                name=name,
                metadata={_SPACE_KEY: _COSINE, _DIM_KEY: self.dim},
                # 见模块 docstring 第 3 条：禁止 Chroma 用自带 EF
                embedding_function=None,
            )
        except Exception as exc:
            raise VectorStoreError(
                f"获取 Chroma 集合失败（{name}）：{type(exc).__name__}: {exc}"
            ) from exc
        self._collections[kb_id] = collection
        return collection
```

🔻 **`embedding_function=None` 不能省**（同文件 L19-L23）：

```
3. **显式传 `embedding_function=None`**：不传的话 Chroma 会把默认的
   ONNX all-MiniLM 记进集合配置，一旦有人写了 `add(documents=...)` 而没给向量，
   它会**静默下载 79MB 模型**再算一组 384 维向量（维度不符才报错）。
```

**79MB 的静默下载**：在离线环境里这会直接失败，而在有网环境里它会
"成功但用错模型"——两个都很糟。显式传 `None` 让这条路**不可能发生**。

**`hnsw:space` 只在创建集合时生效**：这是 Chroma 的行为，
所以本项目把集合命名成 `knowflow_kb_{kb_id}`——**删 KB = drop 集合**
（阶段 8 用它），重建集合时参数才会重新生效：


### 2.9 关键代码 8：metadata 的 None 会被静默丢弃

```python
# backend/src/knowflow/vectorstore/base.py L167-L208（节选）
def sanitize_metadata(kb_id: int, metadata: Mapping[str, Any]) -> dict[str, Any]:
    """把调用方给的 metadata 规范成两个后端都能接受、且**完全一致**的形式。

    做四件事：

    1. **强制覆盖 `kb_id`**：以方法入参为准。KB 隔离是检索正确性的底线，
       调用方写错 kb_id 时不能让错值进库（过滤条件依赖它）。
    2. **校验必含键**：`doc_id` / `doc_name` / `chunk_index` 缺失直接抛错。
       它们是回表 JOIN 与按文档删除的依据，缺了会在检索之后才炸，很难定位。
    3. **丢掉值为 None 的键**：这是 Chroma 的实测行为（写入时静默丢弃），
       内存实现必须跟着丢，否则两个后端返回的 metadata 一个有一个没有。
    4. **标量类型收敛**：`doc_id` / `chunk_index` / `page_no` 强制 `int`。
       Chroma 的 `where` 比较是**强类型**的，传字符串 `"3"` 去比 `{"doc_id": 3}`
       会一条都查不到而且不报错 —— 这类静默查空必须在写入口拦住。
    """
    missing = [key for key in REQUIRED_METADATA_KEYS if metadata.get(key) is None]
    if missing:
        raise VectorStoreError(
            f"向量 metadata 缺少必含键 {missing}（契约要求 {REQUIRED_METADATA_KEYS}），"
            f"现有键：{sorted(metadata)}"
        )

    result: dict[str, Any] = {"kb_id": int(kb_id)}
    for key, value in metadata.items():
        if value is None:
            continue
        ...
```

**"丢掉 None"这个行为必须两个后端**都做**，理由是最难查的一类 bug：

> 同一份代码换后端 → 结果不同。

内存后端如果保留 `page_no: None`，Chroma 后端丢掉，那么
"取 `metadata['page_no']`"在内存后端返回 `None`、在 Chroma 后端抛 `KeyError`。
所以契约写的是：

```python
# backend/src/knowflow/vectorstore/base.py L18-L21
# 5. `metadata` 的值**不允许是 None**：实测 Chroma 写入时会**静默丢弃** None 值的键
#    （写完 `get()` 回来那个键就没了）。所以两个实现统一在 `sanitize_metadata`
#    里丢弃 None，保证返回的 metadata 一模一样。
#    ⚠️ 下游取值请统一写 `metadata.get("page_no")`，不要写 `metadata["page_no"]`。
```

**注意最后一行是"使用约定"**：实现层丢掉了 None，但下游仍然要写 `.get()`——
因为被丢掉的是**键**，不是值。This is why 附录 A 里有一条
`KeyError: 'vector_id'`（BM25 payload 漏字段 → 孤儿向量）。

### 2.10 关键代码 9：`where` 的硬性限制必须在进门时校验

```python
# backend/src/knowflow/vectorstore/base.py L211-L238（节选）
def validate_where(where: Mapping[str, Any] | None) -> None:
    """校验 Mongo 风格过滤表达式，不支持就抛**清晰**错误。

    为什么必须显式校验而不是「透传给后端」：Chroma 只支持固定的几个算子，
    传 `$regex` 会抛它自己的 ValueError（消息里全是 Chroma 内部术语）；
    而内存实现如果不校验就会**静默忽略**这个条件，返回一堆不该返回的结果。
    同一份代码换后端结果不同是最难查的 bug，所以两个后端进门先跑同一个校验器。

    规则全部来自对 chromadb 1.5.9 的实测（报错原文记在注释里）：

    1. **每一层只允许一个键**：`{"doc_id": 1, "page_no": 2}` 在 Chroma 里抛
       `Expected where to have exactly one operator`。多条件要写成
       `{"$and": [{"doc_id": 1}, {"page_no": 2}]}`；
    2. `$and` / `$or` 的值必须是**至少两个**条件的列表；
    3. 一个键后面只能跟**一个**算子：`{"page_no": {"$gte": 1, "$lte": 5}}` 非法；
    4. `$contains` / `$not_contains` 明确拒绝：它们只对列表值生效，
       而本项目 metadata 只有标量，传了必然静默查空。
    """
    if where is None:
        return
    if not isinstance(where, Mapping):
        raise VectorStoreError(f"where 必须是 dict，收到 {type(where).__name__}")
    if len(where) != _WHERE_LEVEL_KEYS:
        raise VectorStoreError(
            f"where 每层只允许一个条件（Chroma 的硬性限制），收到 {sorted(where)}；"
            '多条件请写成 {"$and": [{"k1": v1}, {"k2": v2}]}'
        )
```

**"报错原文记在注释里"这个做法值得学**：`Expected where to have exactly one operator`
是 Chroma 的原话。把它抄进注释，下一个人遇到这个报错时**能搜到本文件**。
不抄的话，这个错误信息在网络上都很难搜到对应解释。

### 2.11 关键代码 10：Chroma 返回值形状的两个陷阱

🔻 **`get()` 一维、`query()` 二维**。混用的后果是**静默返回空列表**——

而实际上有一万个向量。**这是最耗时间的一类 bug**：现象与原因完全不搭。

另外两个空输入：

```python

        return 0
```

```python

    if not targets:
        return 0
```

**这两处都做了"提前返回"**：因为 `[]` 是**合法输入**（比如"这篇文档没有块"），

"非法输入才抛异常"的区分，是接口设计的基本功。

## 4. 常见错误

| 错误信息 | 原因 | 解决 |
| --- | --- | --- |
| 检索结果最相似的排到最后（不报错） | 把 Chroma 的 **distance** 当成了 score | 必须 `score = 1.0 - distance` |
| 所有距离都是 `NaN` | 零向量做了 L2 归一化（除以 0） | `l2_normalize` 里 `if norm == 0.0` 返回零向量 |
| `Expected where to have exactly one operator` | `where` 每层有多个键 | 写成 `{"$and": [{"a": 1}, {"b": 2}]}` |
| 按 `doc_id` 过滤一条都查不到（不报错） | 传了字符串 `"3"`，Chroma 比较是强类型的 | `sanitize_metadata` 强制 `int` |
| `page_no` 读回来是 `KeyError` | Chroma 静默丢弃了 `None` 值的 metadata 键 | 下游统一写 `metadata.get("page_no")` |
| `ValueError: Expected ids to be a non-empty list` | `delete(ids=[])` 或空 `upsert` | 空输入提前 `return 0` |
| 一次 `delete()` 拿到 `dict` 一次拿到 `int` | Chroma 返回 `{"deleted": N}` | 用 `_deleted_count` 抹平 |
| 第一次写向量时静默下载 79MB ONNX | 没传 `embedding_function=None` | 显式传 `None` |
| 改了 `hnsw:space` 但已存在的集合不生效 | 该参数只在**创建**集合时生效 | drop 集合重建（本项目 collection 按 KB 隔离，天然可重建） |
| 返回空列表，但库里明明有向量 | `query()` 是二维返回、`get()` 是一维，混用了 helper | `_first_row` vs `_flat_str_list` 分开 |
| `list_collections` 返回的是字符串而不是对象 | chromadb 0.x 版本差异 | `_iter_collections` 里 `isinstance(item, str)` 分支 |
| `/health` 报 `local` 但实际跑 hash | 降级状态没走 `get_embedder_status` | 统一从 `status.mode` 取 |
| `ModuleNotFoundError: No module named 'torch'`（本应能跑 hash 兜底） | 模块级 `import torch` | `TYPE_CHECKING` + 方法内 import |
| 模型加载报维度不匹配 | 换了 embedding 模型但没清向量库 | `EMBEDDING_DIM` 改对 + drop 集合重新入库 |
| 启动日志刷满 `FutureWarning: get_sentence_embedding_dimension` | sentence-transformers 6.x 改名 | `_read_embedding_dim` 双路 `getattr` |
